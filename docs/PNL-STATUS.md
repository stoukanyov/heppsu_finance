# Състояние на функцията P&L (Отчет за приходите и разходите / ОПР)

_Отчет спрямо първоначалните изисквания. Дата: 25.07.2026._

## Кратко резюме

**Преди тази итерация P&L липсваше.** Модул `reports` съдържаше само:
- Оборотна ведомост (`trial-balance`)
- Главна книга по сметка (`general-ledger`)

Нямаше Отчет за приходите и разходите, макар че сметкопланът вече разграничава
типовете сметки (`AccountType.REVENUE` / `AccountType.EXPENSE`), т.е. данните за
ОПР са налични, но не се агрегираха в отчет.

**Сега P&L е реализиран, тестван и интегриран в UI-то.**

## Какво е реализирано

### Backend
- `app/modules/reports/service.py` → `profit_and_loss(db, company_id, date_from, date_to)`
  - Потоков отчет за периода: работи с **оборотите** (движенията), не с крайни салда.
  - Приходи = кредитен нетен оборот на сметките от тип `REVENUE`.
  - Разходи = дебитен нетен оборот на сметките от тип `EXPENSE`.
  - Финансов резултат = приходи − разходи (`net_profit`, `is_profit`).
  - Взимат се само осчетоводени операции (`POSTED/REVERSED/REVERSAL`); черновите не участват.
  - Периодизация по `document_date` (счетоводната дата), както при другите справки.
- Схеми: `ProfitAndLossOut`, `PnlSection`, `PnlLine` (по сметки, с код/име/сума).
- Endpoint: `GET /api/v1/reports/profit-and-loss?date_from=&date_to=` (tenant-scoped).

### UI
- Нов екран **„Отчети"**: раздели Приходи / Разходи по сметки, финансов резултат,
  филтър по период, плюс оборотната ведомост.
- **Начален екран (дашборд)** използва ОПР за:
  - барова графика „Приходи срещу разходи";
  - донат „Разходи по категории" (реални разходни сметки от ОПР).

### Тестове
- `tests/test_reports.py`: печалба, загуба, филтриране по дати.
- Всички минават (пакетът е зелен).

## Известни ограничения и следващи стъпки
1. **Формат по НСС/МСФО** — текущата разбивка е по синтетични сметки. Групиране по
   раздели на официалния ОПР (нетни приходи от продажби, разходи за материали,
   външни услуги, персонал, амортизации, финансови приходи/разходи) предстои — ще се
   направи чрез мапинг „сметка → ред от ОПР" (аналогично на клетките в ДДС модула).
2. **Сравнителен период** — колона „предходен период" и % изменение (дашбордът вече е
   готов да ги покаже, липсва само backend сравнението).
3. **Баланс (счетоводен баланс) и Отчет за паричните потоци** — още не са реализирани;
   логично следват P&L.
4. **Данъчен финансов резултат** (преобразуване по ЗКПО) — отделна тема, свързана с
   бъдещия Tax Engine (виж `docs/ARCHITECTURE-TAX-ENGINE.md`).
