# Heppsu Finance — мобилно приложение

Flutter клиент към **AI Finance OS** (`apps/api`). Добавка към уеб приложението, не негов заместител:
телефонът е за **сканиране на документи**, **одобрения** и **бърз поглед към числата**.

## Какво прави

| Стълб | Поток |
|---|---|
| **Сканиране** | Снимаш фактура/касова бележка → изображението се смалява на телефона → `POST /documents/scan` → сървърът пази оригинала и го OCR-ва → показва разпознатите данни **и предложената счетоводна статия** → натискаш „Потвърди осчетоводяване" |
| **Срокове** | Предстоящите задължения към НАП/НСИ/Търговския регистър, с напомняния **7 дни, 3 дни и 24 часа** преди всеки срок |
| **ДДС** | Списък с месечните ДДС отчети → детайл с клетките на справка-декларацията → **Одобри** (приключва периода) или **Откажи** (връща за корекция) |
| **Отчети** | KPI карти, ОПР по статии, и продажби от App Store / Google Play |

### Принципи

- **AI предлага, човек потвърждава.** Статията се създава като чернова (`DRAFT`);
  осчетоводява се само след изричен натиск на бутона.
- **Оригиналът се пази на сървъра** (`Document.storage_path`). Смалява се само това,
  което тръгва по мрежата.
- **Мултитенант.** Всяка заявка носи `Authorization: Bearer <JWT>` + `X-Company-Id`.
- **Мобилното не извършва плащания** — само одобрява.

## Смаляване на изображенията

`lib/core/scan/image_pipeline.dart` — работи в отделен isolate, за да не блокира UI-а:

1. Ресайз до **2200px** по дългата страна (само надолу — малки снимки не се пипат).
2. JPEG **quality 80**.
3. Ако файлът още е над **4 MB** — качеството слиза стъпаловидно до 40.
4. Ако и това не стигне — слиза и резолюцията, но **никога под 1000px** (граница за четимост на OCR).
5. Изчислява се `sha256` (backend дедупликира по него).

Екранът за преглед показва колко е спестено: „Смалено: 3120 KB → 284 KB (−91%)".

## Напомняния за срокове

Известията са **локални** (`flutter_local_notifications`) — планират се на самия телефон,
без Firebase и без сървърна push инфраструктура. За всеки срок се насрочват три:

| Кога | Текст |
|---|---|
| 7 дни преди | „… — след една седмица" |
| 3 дни преди | „… — след 3 дни" |
| 24 часа преди | „… — утре" |

Звънят в 9:00 местно време. При всяко зареждане на екрана „Срокове" известията се
пренасрочват, така че преместен или отпаднал срок не оставя стара нотификация
(идентификаторът е производен на `key` + отместването, затова няма дубликати).

Сроковете идват от `GET /deadlines/upcoming` — backend-ът ги изчислява и вече е преместил
онези, които падат в събота, неделя или официален празник.

Потребителят включва напомнянията с превключвателя на екрана; тогава се иска системното
разрешение. Изборът се пази в secure storage.

## Стартиране

```bash
cd apps/mobile
flutter pub get
flutter run --dart-define=API_BASE_URL=http://localhost:8000
```

Base URL по подразбиране е `http://10.0.2.2:8000` (хостът, видян от Android емулатора)
и `http://localhost:8000` за web/десктоп. За реален телефон подай IP-то на машината:

```bash
flutter run --dart-define=API_BASE_URL=http://192.168.1.10:8000
```

Backend-ът се пуска отделно — виж `apps/api`.

## Тестове

```bash
cd apps/mobile && flutter test
```

Покрити са двете най-крехки места: компресията (`image_pipeline_test.dart`) и парсването
на API отговорите (`models_test.dart`) — включително `Decimal` полетата, които FastAPI
праща като низове.

## Структура

```
lib/
├── main.dart                    # рутиране по състояние на сесията
├── app/
│   ├── providers.dart           # Riverpod: сесия, repositories, данни за екраните
│   └── theme.dart
├── core/
│   ├── config/app_config.dart   # API_BASE_URL, таймаути
│   ├── network/                 # dio клиент + Bearer/X-Company-Id, ApiException
│   ├── security/secure_store.dart  # JWT в Keychain / Keystore
│   └── scan/image_pipeline.dart # смаляване + sha256
├── domain/models.dart           # огледало на Pydantic схемите
├── data/repositories.dart       # Auth · Documents · Vat · Reports
└── features/
    ├── auth/        (login, избор на компания)
    ├── shell/       (долна навигация + бутон „Сканирай")
    ├── scanner/     (избор на източник → преглед → качване)
    ├── documents/   (списък, детайл, PostingCard)
    ├── deadlines/   (срокове + превключвател за напомняния)
    ├── vat/         (периоди, детайл с одобри/откажи)
    └── reports/     (KPI, ОПР, магазини)
```

`core/notifications/reminder_service.dart` държи планирането на известията.

## Разрешения

- **iOS** (`Info.plist`): камера, галерия, Face ID. Нотификациите се искат при включване.
- **Android**: интернет, `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED` (напомнянията да
  преживеят рестарт); камерата е `required="false"` (може и от галерията).
  `network_security_config.xml` пуска cleartext **само** за localhost/10.0.2.2 — прод е HTTPS.

## Още не е реализирано

Съзнателно отложено, за да има работещ край-до-край поток първо:

- Offline опашка (drift + workmanager) — сега сканът се качва веднага.
- Сървърни push нотификации (FCM) — напомнянията за срокове вече работят локално,
  но събития като „документ разпознат" от друг канал още не стигат до телефона.
- Биометрично отключване и certificate pinning.
- Многостранични PDF сканове и edge detection (`cunning_document_scanner`).

Пълната целева архитектура е в `docs/MOBILE-ARCHITECTURE.md`.
